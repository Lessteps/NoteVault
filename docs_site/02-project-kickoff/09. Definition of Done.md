# 09. Definition of Done & Ready

**Fase:** 02 — Project Kickoff  
**Entregable:** 09  
**Proyecto:** NoteVault (PC, Mac, Android, iPhone)

---

## 1. Definición de Listo (Definition of Ready - DoR)

Un requerimiento o tarea solo puede pasar a desarrollo si cumple:
- [ ] Especificación de módulo asignada (`MOD-01` a `MOD-09`).
- [ ] Impacto en el contrato de bóveda (`docs/VAULT_FORMAT.md`) documentado y acordado.
- [ ] Criterios de aceptación funcionales definidos en lenguaje verificable (Dado-Cuando-Entonces).
- [ ] Mockup o especificación ergonómica revisada para Desktop y Mobile.

---

## 2. Definición de Terminado (Definition of Done - DoD)

Una tarea solo se considera terminada si cumple:
- [ ] Código implementado con tipado estricto sin advertencias del linter.
- [ ] Pruebas unitarias escritas con cobertura > 85% para la nueva lógica.
- [ ] `npm run typecheck` en Desktop pasa con 0 errores.
- [ ] `flutter test` en Mobile pasa con 0 errores.
- [ ] Pruebas de conformidad superadas sin diferencias de bytes en el formato serializado.
- [ ] Documentación técnica actualizada si hubo cambios de contrato.

---

## 3. Marco Conceptual: Criterio de Terminación de Ingeniería

<div class="entity-card">

1. **Entidad principal e independiente.**
2. **Es la entidad líder del conjunto de datos:** posee un identificador global único que fija el estándar de admisión y salida de trabajo (`dod_policy_id`: `DOD-ZERO-REGRESSION-LOCAL`) consultado en las revisiones de código.
3. **Existe por sí misma en el acuerdo de trabajo del equipo sin depender de la urgencia del sprint**, y es la única responsable de asegurar que no se introduzca deuda técnica ni regresiones en la base de datos de archivos.
4. **Punto de entrada y límite de consistencia:** Ningún ticket se marca como "Done" sin verificación completa de la lista.
