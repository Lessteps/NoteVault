## 1. Topología Física de Repositorios

El ecosistema se organiza en dos repositorios complementarios:

### Repositorio Principal: `NoteVault` (Desktop Core)
```
NoteVault/
├── frontend/                          Aplicación Electron + React
│   ├── electron/                      Main process (main.ts) y Preload (preload.ts)
│   ├── src/                           Código fuente TypeScript (core/, api/, components/)
│   └── package.json                   Dependencias y scripts de compilación
├── docs/                              Contratos normativos originales (VAULT_FORMAT.md)
├── docs_site/                         Portal de documentación completa MkDocs
├── tools/                             Herramientas de renderizado y validación de canvas
└── mkdocs.yml                         Configuración de documentación MkDocs
```

### Repositorio Móvil: `notevault_mobile` (Mobile Core)
```
notevault_mobile/
├── lib/
│   ├── core/                          Modelos de datos simétricos y gestores en Dart
│   ├── ui/                            Pantallas Flutter (screens/, widgets/, theme/)
│   └── main.dart                      Punto de entrada de Android e iOS
├── android/                           Configuración nativa de Android y Gradle
├── ios/                               Configuración nativa de Xcode para iPhone/iPad
└── pubspec.yaml                       Dependencias oficiales de Flutter
```

## 2. Marco Conceptual: Topología de Monorepo / Multi-Repo

<div class="entity-card">

1. **Entidad principal e independiente.**
2. **Es la entidad líder del conjunto de datos:** posee un identificador global único que fija la estructura de carpetas física (`repo_topology_id`: `TOPOLOGY-DUAL-REPO-ALIGNED`) consultado en los scripts de CI/CD.
3. **Existe por sí misma en el sistema de control de versiones sin depender de subárboles temporales**, y es la única responsable de garantizar la modularidad y separación de responsabilidades entre el cliente de escritorio y el cliente móvil.
4. **Punto de entrada y límite de consistencia:** Define los límites de compilación y las rutas canónicas relativas.
