> **Audience:** an AI assistant working on NoteVault, most likely porting the
> desktop app's features and interface to the Android client in a separate
> session. Read this whole file before changing code.
>
> **Canonical copy:** `NoteVault/docs/AI_HANDBOOK.md` (desktop repo). A copy
> lives in `notevault_mobile/docs/AI_HANDBOOK.md`; when they differ, the
> desktop copy wins. Last verified against the source on 2026-09-12.

---

## 1. What NoteVault is

A personal productivity app built around an Obsidian-style folder of markdown
notes (the **vault**), with five modules on top of it:

| Module | Spanish UI name | What it does |
|---|---|---|
| Dashboard | Vista General | Today at a glance across all modules |
| Habits | Hábitos / Habit Tracker | Daily habit checklist, journal, stats, streak heatmap |
| Exercise | Ejercicio | Weekly gym routine, per-set logging, demo videos |
| Tasks | Tareas | Task database, calendar, reminders with notifications |
| Projects | Proyectos | Projects with a checklist of dated steps |
| Notes | Notas | Obsidian-like markdown editor over the vault |

The UI language is **Spanish**. Keep every label in Spanish; this document is in
English only so that it is unambiguous for an AI.

### Two apps, one contract

| | Desktop | Mobile |
|---|---|---|
| Repo | `Lessteps/NoteVault` | `Lessteps/notevault_mobile` (private) |
| Local path | `C:\PROGRAMMING\NoteVault` | `C:\PROGRAMMING\notevault_mobile` |
| Stack | Python 3.13 + PySide6 (Qt 6), packaged with PyInstaller as `NoteVault.exe` | Flutter / Dart, Android (API 26+) |
| Entry | `app_entry.py` → `notevault_app/main.py` | `lib/main.dart` |

**There is no server and no database.** Both apps read and write the same files
in the same vault folder, synced between devices with Syncthing. The file format
is the only interface between them. Consequences that are not negotiable:

1. **Any change to the file format lands in both apps in the same piece of work.**
   `notevault_app/core/vault_format.py` and `lib/core/vault_format.dart` must
   agree on every constant.
2. **Writers must produce byte-identical files.** A Dart write of a task must
   match what Python writes, or two devices produce endless sync diffs.
   `notevault_mobile/test/conformance_test.dart` asserts this against fixtures
   generated by the desktop (`python tests/test_vault_format.py --write`).
3. **A client that reads a field it does not understand must write it back
   untouched.** (Known gap: the desktop `TaskManager.save` / `ProjectManager.save`
   currently rewrite only the known keys.)

## 2. The vault format (summary)

The human contract is `NoteVault/docs/VAULT_FORMAT.md` (Spanish, authoritative).
`FORMAT_VERSION = 2`.

```
vault/                                   any folder the user picks (often their Obsidian vault)
├── .notevault/                          ALL module data, one folder so it syncs as a unit
│   ├── habits/
│   │   ├── habits_config.json           global
│   │   └── YYYY/MM/YYYY-MM-DD.md        one file per day
│   ├── ejercicio/
│   │   ├── exercises.json               global, a bare JSON array
│   │   ├── videos/<file>.mp4            exercise demo videos
│   │   └── YYYY/MM/YYYY-MM-DD.json      one log per day
│   ├── tareas/<task-id>.md              one file per task
│   └── proyectos/<project-id>.md        one file per project
├── .notevault-bookmarks.json            global, relative posix paths
└── <anything>/…                         the user's notes; media in `attachments/` beside a note
```

- **Version 1 → 2 migration:** the four module folders used to sit at the vault
  root. Both apps move them under `.notevault/` on open and never overwrite: if
  the destination file exists it wins and the legacy copy stays on disk.
- **Dates** `YYYY-MM-DD`; **date-times** `YYYY-MM-DDTHH:MM`, local time, no zone.
- **Weekdays:** `0 = Monday`. Weekday keys: `lunes martes miercoles jueves viernes
  sabado domingo` (no accents).
- **Sync-conflict files** contain `.sync-conflict-` and are always ignored.

### Habits
- `habits_config.json`: `{"version": 3, "habits": [{id, name, icon, days: [0..6], subtasks: [{id, name}]}]}`.
  Empty or missing `days` = every day. 15 default habits are installed when there is no config.
- Day file: frontmatter with `date`, a `completed:` map (2-space indent, every configured
  habit, `true`/`false`), `notes: "…"`, optional one-line JSON `subtasks: {"habit": {"sub": true}}`.
  Everything after the closing `---` is the day's journal.
- Day % = completed ÷ habits **active on that weekday** (0 if none).
- Week/month % = mean of daily % up to today. Year % = mean of the monthly means above 0.

### Exercise
- Exercise: `{id, day, name, video, video_path, series_reps, rest, how_to}`; id `<daykey>_<n>`.
- Every day gets an "Estiramientos" exercise if it has none (`<day>_estiramientos`).
- Log: `{"<exercise_id>": {"done": bool, "weight": float, "reps": int, "notes": str}}`, 2-space indented JSON.
- Video lookup: `video_path` if it exists on this device, else `.notevault/ejercicio/videos/<video>`.

### Tasks
- Frontmatter keys **in this exact order**: `id, name (quoted), created, start, due, status,
  subject (quoted), priority, reminder, reminder_done`. Empty dates are the bare key (`start: `).
  Body = free markdown.
- Id `t<YYYYMMDD>-<6 hex>`. Statuses: `Sin empezar`, `En progreso`, `Completado`, `Bloqueado`.
  Priority 1–3.
- `reminder_done` becomes `true` once **any** device has shown the reminder; it is the flag that
  stops desktop and phone from both notifying.

### Projects
- Frontmatter: `id, name (quoted), status, color (quoted hex), created, start, deadline`.
- Body: free description, then `## Tareas`, then one step per line: `- [ ] name` or
  `- [x] name | YYYY-MM-DD`.
- Id `p<YYYYMMDD>-<6 hex>`. Statuses: `Planeado`, `En curso`, `Pausado`, `Terminado`.
- Progress is **derived** (done steps ÷ steps), never stored.

### Reminder rules (must be reproduced exactly)
A task yields a reminder only if it has `reminder`, `reminder_done` is false and it is not
`Completado`.
- **due now:** `when <= now` and `now - when <= 2 days`.
- **stale:** older than 2 days → marked shown **without** notifying.
- **upcoming:** `now < when <= now + 14 days`, at most 60, sorted.
- Notification key `task:<id>`. One reminder: title "Recordatorio de tarea", body `• name · subject · vence dd/mm`.
  Several: "N recordatorios de tareas", one bullet per line.

### Notes and attachments
- Notes are any `.md` outside `.notevault/`. Wikilinks `[[Title]]` / `[[Title|alias]]`.
- Media pasted or dropped into a note is **copied** to `attachments/` beside the note and embedded
  as `![](attachments/file.png)` (angle brackets when the path has spaces:
  `![](<attachments/my file.png>)`). Names never overwrite: `file 1.png`.
- Obsidian embeds `![[file.png]]` are read too (lookup: note folder → its `attachments/` → vault
  root → search by name) and written back unchanged.
- `attachments/` is never listed in a notes explorer.

(`notevault_app/ui/theme.py` holds the full dark→light map). The mobile port mirrors both in
`lib/ui/theme/nv_theme.dart`.

### Components the user explicitly cares about
The user rejects "equivalent" substitutes. Replicate these exactly:

- **Square-block progress bar** (`ProgressBlocks`): 10 square blocks, 11×11 px, radius 2, gap 2,
  filled = `round(pct × 10)`, fill `#4ade80`, empty `#c9c9cf`, followed by `NN%`.
  Never a continuous bar where the desktop uses blocks. (Exercise Registro and project cards are
  the two places the desktop uses a *continuous* thin bar.)
- **Square checkbox** (`NotionCheck`): empty square, radius 3, border `#6a6a72`; checked = filled
  accent with a white ✓. Never a filled colour button, never a round radio.
- **Module cards:** radius 10–12, a 2 px **top border in the module accent**, title "icon  Title"
  left, accent subtitle right (e.g. `3/13`).
- **Tables:** 38–40 px rows, hairline row separators, 1 px column separators, uppercase column
  headers with a leading glyph (`Aa  NOMBRE`, `◌  ESTADO`, `★  PRIORIDAD` …).
- **Streak heatmap:** GitHub-style, 7 rows (Mon–Sun) × weeks, 13 px cells, 3 px gaps; colours
  0 → `#161b22`, <0.4 → `#216821`, <0.8 → `#2ea043`, ≥0.8 → `#4ade80`; future days `#111111`.
- Fonts: `Segoe UI Variable Text` for UI and notes; `Cascadia Mono` only for raw source.

## 4. Desktop shell

A 44 px **icon rail** on the left (top to bottom): ☰ toggle panel · ◎ Vista General · ⊙ Habit
Tracker · 🏋 Ejercicio · ◫ Proyectos · ✎ Notas · ☑ Tareas · (bottom) ◑ theme. Then a horizontal
splitter of **left panel · center · right panel**:

| Mode | Left panel | Center | Right panel |
|---|---|---|---|
| Vista General (start) | — | Dashboard | — |
| Habits | view list | active habit view | Estadísticas |
| Ejercicio | view + weekday list | active exercise view | — |
| Tareas | view list | active task view | — |
| Proyectos | board + project list | board or project detail | — |
| Notas | file explorer / search / bookmarks | editor | AI assistant (toggleable) |

**Mapping to mobile** (what the existing port already does, keep it consistent):
icon rail → bottom `NavigationBar` with the six modules in the same order; a module's left-panel
entries → a horizontal segmented switcher (`NvViewSwitcher`) at the top of the screen; right panel
→ a section inside the screen or a bottom sheet; desktop dialogs → full-screen routes.

### 5.6 Notas (desktop, Obsidian-like)
Files: `ui/components/notes/` — `notes_sidebar.py`, `markdown_editor.py`, `note_view.py`,
`command_palette.py`, `file_icons.py`, `md_highlighter.py`, `ai_chat_panel.py`; core
`notes_service.py`, `qt_markdown.py`, `vault_index.py`, `attachments.py`, `file_kinds.py`.

**Explorer (left).** Tabs Files · Search · Bookmarks. Lazy tree (one level read per expand).
- Lists **notes (`.md`) and source-code files** (`.py .js .ts .jsx .tsx .java .kt .go .rs .c .cpp .cs
  .rb .php .swift .dart .lua .r .scala .sh .ps1 .bat .sql …`). Notes get a page icon; code files a
  coloured language badge ("PY", "TS", …). Never lists `.notevault/`, dot-folders, tooling folders
  (`node_modules`, `venv`, `dist`…) or `attachments/`.
- **Natural numeric order:** every digit run compares as a number — "0.4" < "1.2" < "1.10",
  "Fase 2" < "Fase 10"; numbered names before unnumbered. Folders first.
- Context menu: open, bookmark, new note/folder here, open all notes in folder, rename, move to
  `.trash`.

**Editor (center).**
- **Tabs:** reorderable; **pinnable** (📌 prefix, no close button, stay leftmost, cannot be closed,
  reopen with the vault). Right-click menu: "Fijar/Desfijar pestaña", "Cerrar", "Cerrar las demás",
  "Cerrar las de la derecha", "Cerrar todas (salvo fijadas)", "Copiar ruta", "Revelar en el
  explorador", "Mostrar en la carpeta de Windows". Ctrl+W closes (not pinned).
- **Modes:** "Editor" (rich, WYSIWYG), "Markdown" (raw source, monospace), "Lectura" (read-only
  render). Code files always open in the raw view with formatting disabled and are saved verbatim.
  Which mode a note opens in is decided **once, when it is loaded**, and remembered for as long as it
  stays open; recomputing it on every capture re-parsed the whole note and stalled the editor a second
  after every keystroke.
- **Markdown mode is a first-class writing surface**, not a fallback: most notes live there.
  `md_highlighter.py` colours the source the way Obsidian's source mode does — headings sized and
  tinted with their `#` dimmed, bold/italic/strikethrough/`code`/`==highlight==`, links, `[[wikilinks]]`
  and `#tags`, list bullets, `[ ]` / `[x]` boxes (a ticked item's text struck through), quote markers,
  table pipes, rules, fenced code and the YAML frontmatter. The highlighter is switched off for source
  files, whose `#` and `*` are not markdown. Re-running it never marks the note as edited.
  Enter continues a bullet, a numbered item (renumbered), a task (`- [ ]`) or a quote, and an empty item
  ends the list instead of leaving a dangling bullet; Tab / Shift+Tab move an item (or a whole
  selection) one level; typing `*`, `` ` ``, `_`, `~`, `[`, `(` or `"` with text selected wraps it
  instead of replacing it.
- **Safety rule:** the Editor saves by re-serialising the document. Before a note is shown in Editor
  mode, `rich_edit_problem()` imports and re-serialises it in memory; if any word, checkbox, table row,
  image, heading or code fence would be lost, or the text would change on a second pass, the note opens
  in Markdown mode instead and the Editor button is disabled with the reason. (~92% of the user's real
  notes pass.) Any port must keep an equivalent guarantee: **never autosave a lossy re-serialisation.**
- **Checklists & lists:** task items `- [ ]` / `- [x]` render as square checkboxes that toggle on
  click (also in Lectura, which edits the source line directly); Ctrl+L toggles the current item.
  Nested lists show **vertical indentation guides** positioned at the start of each ancestor's text
  (Obsidian style). Tab / Shift+Tab move an item down/up a level; Enter on an empty item climbs a level
  then exits the list; Enter after a task starts a new unchecked task. Typing "- ", "* ", "1. ",
  "[ ] " or "- [ ] " at line start converts the line into that list.
- **Tables are interactive in both editing modes.** In Editor mode they are real grids with a shaded
  header row; Tab moves to the next cell and Tab in the last cell appends a row. In Markdown mode the
  same commands rewrite the aligned pipes of the table under the caret, and Tab re-aligns it and moves
  to the next cell. Right-click "Tabla ▸" and the palette offer: add row above/below, add column
  left/right, delete row/column/table, and — in Markdown mode — set the column's alignment. Saved as a
  **GitHub table with aligned pipes** (column widths by display width, wide glyphs count 2;
  `:---:` / `---:` alignment kept).
  A rendered table **takes the full writing width** (`QTextLength.PercentageLength, 100`) and shares it
  between its columns, so a long cell wraps onto several lines. Letting the table hug its longest line,
  which is Qt's default, is the single thing that makes it not look like the reference.
  "Insertar tabla…" opens `table_picker.py`, the hover grid every editor has: up to 8 × 8, the label
  says "4 × 5 · cabecera + 3 filas de datos", arrows adjust, Enter inserts, Esc cancels.
- **Rendered typography** (`style_document()` in `note_view.py`): Qt's markdown importer stacks every
  block flush against the next, so after the import the views add paragraph, heading and list spacing,
  indent quotes behind a coloured vertical bar, shade fenced code, put `inline code` on a chip, and
  give tables margins, top-aligned cells and a bold header. Only block margins and backgrounds are
  touched; `document_to_markdown()` reads neither (it decides what is a code span from the font
  family, never the background), which is verified against the whole vault — the styling must never
  change a byte that reaches a file.
- **Task checkboxes are painted by hand** (`_paint_checkbox`), not left to Qt. Qt draws its marker
  flush against the first character, so the box and the label read as one word and there is no API for
  the gap. The painter covers the marker slot with the page colour and draws a rounded square
  `BOX_GAP` pixels before the text: hollow with a grey border when open, filled with the accent and a
  white tick when done. A port on another toolkit needs the same result, not the same technique.
- **Ctrl+P command palette:** floating search box; accent-insensitive multi-word filter; ↑↓ Enter Esc.
  Commands grouped "Tabla", "Checklist", "Lista", "Adjunto", "Formato", "Vista", "Pestaña", "Nota";
  commands that do not apply (e.g. row commands outside a table) are listed but disabled. The shortcut
  is registered with `Qt.WindowShortcut`, not `WidgetWithChildrenShortcut`: it used to do nothing
  whenever the focus sat in the file tree or the assistant, which is exactly where it is right after
  clicking a note. Opening a note also moves the focus to the visible view. Ctrl+Shift+P is an alias,
  Ctrl+E toggles Lectura, Ctrl+Shift+T inserts a table.
- **Attachments:** paste an image, drop files, or "📎 Insertar imagen o video". Files are copied to
  `attachments/` beside the note (see §2). Images render inline scaled to the editor width; videos render
  as a poster card with a play button and open the embedded player on click (double-click in Editor).
- **Toolbar:** H1 H2 H3 ¶ · B I S </> · A+ A− · • 1. ☑ ❝ ⊞ · 🔗 [[ ]] 📎 ― · ⌘ palette · 🔖 bookmark ·
  Editor / Markdown / Lectura.
- **Mentions footer:** "Linked mentions" / "Unlinked mentions" for the open note, computed on a single
  worker thread, capped at 60 rows per section ("… y N más."). Not recomputed on autosave, and not
  computed at all while the footer is collapsed.
- Autosave 1200 ms after typing; YAML frontmatter is split off and re-attached untouched. Paths longer
  than 260 characters are opened with the Windows `\\?\` prefix.

**The vault text index (`core/vault_index.py`).** Backlinks and full-text search both need to read
every note. On a real vault that is ~3,000 files and 10 MB: about 3 s warm and half a minute cold, and
the editor used to pay it on **every note the user opened**, on a thread that holds the GIL — which is
what made the window stop responding. The index reads each file once and keeps its text until the
file's mtime or size changes, so:
- it is filled once in the background shortly after the notes panel is built;
- a backlink scan is a pass over memory (tens of milliseconds);
- a save feeds the new text straight back in (`NotesService.note_written`), so nothing waits for a walk;
- the directory is re-walked at most every 30 s, because stat-ing 3,000 files itself takes seconds;
- search reads the cached copy and never walks from the UI thread, and the search box is debounced
  260 ms — it used to run a full-vault read on every keystroke.
Bookmarks are cached the same way, against the bookmark file's mtime: `is_bookmarked()` is asked once
per note opened and used to re-read the list and stat every entry.

**Other things that were measured and fixed** (numbers from the user's vault, worth re-checking in any
port): restyling a note's tables called `setFormat` per table and relaid the document out each time —
over a second for a note with 74 tables, paid again on every Tab inside a table; wrapping the pass in
one `beginEditBlock` brings it to under 20 ms, and a single table edit restyles only that table.

**AI assistant (right).** "✦  Asistente" panel (providers configured with ⚙: local LM Studio/Ollama or
copy-prompt flows). Toggle with the "✦  Asistente" button on the tab row or the "✕" in the panel header;
the choice is remembered. Actions insert into / replace the selection in the open note or create a note.

## 7. How to work on this codebase

- **Before a UI change, capture the desktop reference.** Run the app and grab each view; the user
  expects element-by-element fidelity (square blocks stay square blocks, checkboxes stay empty squares)
  and has rejected "equivalent" designs. Verify visually before calling work done.
- **Desktop screenshots:** instantiate `MainWindow`, call `_switch_mode(mode)`, `win.grab()`; use
  `QScreen.grabWindow` for popups and video surfaces.
- **Mobile screenshots without a device:** `test/render_screens_test.dart` renders screens against the
  real vault into `test/shots/` with real fonts loaded (`flutter test --update-goldens`); emoji and
  Material icons show as boxes there only.
- **Tests:** desktop `python -m unittest discover -s tests` (vault format conformance, markdown
  round-trip); mobile `flutter test` (conformance against desktop fixtures, screen renders).
- **After any desktop code change**, rebuild and copy the exe:
  `python -m PyInstaller NoteVault.spec --noconfirm` then copy `dist\NoteVault.exe` to the repo root —
  the user launches the app from that exe. New modules must be added to `hiddenimports` in the spec.
- **Performance rules:** never walk the whole vault eagerly or on the UI thread (the user's vault is
  `C:\PROGRAMMING`, with thousands of notes and code folders); no disk access may raise into the UI.
- **Windows shell notes:** PowerShell 5.1 (no `&&`, no heredocs); use Bash for heredocs; set
  `PYTHONIOENCODING=utf-8` when printing emoji; `Get-Content` without `-Encoding utf8` corrupts UTF-8.
