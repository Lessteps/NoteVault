## 3. Work package A — Databases

### 3.1 Numbering (so the natural order is the learning order)

The app orders by the folder number (`6.0` < `6.1` < `6.4.1` < `6.18`). Therefore:

- **Foundations go BEFORE `6.1`** as `6.0.K` (a new group topic `6.0 Databases from zero` and its pieces `6.0.1`, `6.0.2`…).
- **Statement-level pieces go UNDER the existing chapter** that owns them: `6.4.K` under `6.4 CRUD and basic queries`, `6.5.K` under
  `6.5 JOINs and aggregations`, and so on. The existing chapter note stays as it is (it becomes the group overview); do not edit it
  except to add `[[links]]` to its new pieces in a `## Pieces` section.
- **New engines and comparisons take new chapter numbers** after the last one: `6.18`, `6.19`, `6.20`…
- Check what exists before creating anything: `node frontend/tools/programming_kb/status.mjs 6`. A number that already exists is
  never reused.

## 4b. Second pass — the format check (this is what «done» means)

`finalize.mjs` and `links.mjs` do NOT check that a theory note follows the skill. The app does, and the first pass left 217 topics it still
flags (they start `**X is** … **It works like** …` instead of `**In one sentence.** …`, or have `- **- In the practice:**`). Therefore:

1. From `NoteVault/frontend` run `PKB_SPACE=/home/drawn/projects/Lessteps/knowledge-base/Programación node tools/programming_kb/check_format.mjs`
   — it lists every failing topic and what is missing. **After every batch run it on that batch** (`… check_format.mjs "^7\\."`).
2. `DESACTUALIZADOS.md` now lists exactly those topics. Fix them in order; the run is finished ONLY when `check_format.mjs` (no argument) prints
   `0 do NOT follow` and exits 0. Emptying the list by hand is not «done».
3. Models that pass: `1 Fundamentals/1.1 What programming is` (chapter-style) and `6 Databases/6.4.1 SELECT statement` (piece-style). Copy their
   SHAPE (headings, the `**In one sentence.**` opening, numbered mental model, `- **In the practice:**`, the `## Examples` and `## Common mistakes`
   blocks), not their content. Re-read `resumen_teorico_skill.md` before each batch: drifting from it is exactly what produced this second pass.

## 4c. Third pass — short notes, one concept each

The skill now has hard limits («Size and focus» and «Entry level» in `resumen_teorico_skill.md`): `## Explanation` ≤ 500 words (aim 250–350), whole note
≤ 1500 (aim 900–1100), ONE concept per note, no internals in difficulty-1 topics, a language starts with «run your first program».
`check_format.mjs` fails above the limits and the app flags those notes as outdated, so they appear in `DESACTUALIZADOS.md`.
`_handoff/regenerar/NOTAS_PESADAS.md` lists them in route order. Rules for this pass:
- Shorten by cutting, not by moving text around: remove the second and third concept, the internals and every sentence that does not change what the learner types.
- If the title lists several concepts («A, B and C»), create atomic pieces `N.M.1`, `N.M.2`… and leave the parent as a one-screen summary that links them.
- `2.1.1` (Python) must not be topic 1: add `2.1.1.1 Run your first Python program` and `2.1.1.2 Values and print` first, then move project layout, environments and imports to later pieces.
- Done when `check_format.mjs` (no argument) prints `0 do NOT follow` and exits 0.

## 5. Quality bar (both packages)

- Same headings, counts and frontmatter as the skills dictate. A note that does not pass `finalize.mjs` is not finished.
- A piece note goes deep on **one** thing: what it does, every form or value it accepts, the default, what it interacts with, one
  common mistake with symptom and fix, one realistic use. 6–9 Cards about *that* piece only.
- No invented output, no invented behaviour of an engine. If you are not sure of a detail, run it or leave it out.
